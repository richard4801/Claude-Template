## Modes and spending (`SUITE_MODE`)
- `off` is the default in production. Shots refuse with `engine_unavailable`; the catalog says `enabled: false`.
- `mock` is the default everywhere else.
  - Planning and pricing are real: same ladder, same inputs, same estimate.
  - The **mock provider** records the exact provider input it would have sent, then renders a test-pattern mp4 of the right length and shape with ffmpeg.
  - It settles **$0** with the note `· test render`. Set `SUITE_MOCK_CHARGE=true` to settle the real estimate instead, which exercises the money path in dev.
- `live` uses Replicate (`REPLICATE_API_TOKEN`) and fal (`FAL_KEY`). A model whose provider isn't set up is skipped on the ladder.

**Owner: to go live, set `SUITE_MODE=live` on Railway.** Nothing in this workstream spends money until then, and after that only when someone presses Generate.

### Licence flags
Every entry carries these fields:
- `licence.kind`: `hosted` or `open-weights`
- `licence.name`
- `notice`: e.g. "MiniMax H3" attribution
- `territoryExcluded`
- `blockNewFeatures`
- `requiresAck`: the model is hidden until the owner acknowledges it in suite settings

`h3-open` is the MiniMax H3 Community Licence:
- It excludes the US, EU, UK and South Korea, outputs included.
- It requires a "Powered by MiniMax H3" notice.
- It is `blockNewFeatures`: it is never picked, can't be switched on, and is shown to the owner with "Licence: not for new features".

The existing Edit path is untouched; the owner decides that.

**Compiler rules:**
- **Grammar per model family** (prompt keys `suite.camera.format.*`):
  - Kling: short imperatives.
  - Seedance: tagged blocks.
  - H3: camera vocabulary.
  - Veo: descriptive.
  - Everything else: the generic format.
- **Wording:** per option, from `suite.camera.*` lines (`id: wording`). The `{amount}` placeholder scales with intensity, e.g. "about 1.4 m" or "about 120°".
- **One-move rule:** Seedance and LTX drop the mix, and so does any shot under 5 s. Incompatible pairs are dropped too. Every drop comes with a note.
- **Real parameters only where a model has them:** LTX gets `camera_motion` (dolly in/out/left/right, jib up/down, static, focus shift) and the nearest `fps`.
- **Things to avoid** (e.g. "no zoom" on a dolly) go into the negative prompt on Wan. On other models they become a closing sentence.
- **Warnings:**
  - Moves that are cleaner as editor effects: whip pan, crash zoom.
  - Moves that fight lip sync.
  - A guide clip on a model that takes no video.
- **Guide hook** (workstream 2):
  - `camera.guide.video` is sent as the first reference video on models with `referenceVideo` support, with "Take the camera movement and framing from <Video 1>; do not copy its look…".
  - `camera.guide.keyframes` (start/middle/end) become the keyframes.
  - `camera.mode: "directed"` makes a guide-capable model mandatory.

## Shot prompt (owner-editable: `suite.shot.*`)
The prompt is built in this order:
1. Character line: who she is, her images by token, her look, the never-add list.
2. Outfit.
3. One line per extra reference: product, location, style, prop or person.
4. The role lock, when there is more than one role.
5. The keyframes line.
6. The user's prompt and direction.
7. The guide line(s).
8. The camera block.
9. Things to avoid.
10. The footer.

**Tokens per model:** `<Image n>` (H3), `@image_n` (Kling 4.0), `<<<image_n>>>` (Kling 3.0 Omni), `[Image1]` (Seedance), none (Veo, Wan, LTX).

**Character reference subset:** the 7-image sheet plus the outfit, fitted to the model's limit after keyframes and extra references. Face front is never dropped. The priority order is: face, outfit front, profile, body front, outfit ¾, body ¾, …. Images are sent in sheet order.

**Prompts never name a provider or model.** The tests check this.

## Jobs, money and delivery
- **A shot is a render job** with `request.engine: "suite"`, so it gets the same hold → settle → refund, the same `job`/`take`/`balance` SSE events, and the same `DELETE /v1/jobs/{id}` cancel.
  - Its `request` is member-safe: the tier, label, length and the shot spec.
  - The plan, with model and provider, lives in `jobs.stats.suite` and is never in a job view.
- **The suite line** runs on its own, separate from the RunPod pod queue: FIFO, `SUITE_MAX_CONCURRENT` (2) at a time. Prediction ids are saved per take, so a restart resumes polling instead of paying twice.
- **No trim.** Each take is the provider's file as delivered; sound off drops the audio track by stream copy.
- **Settle** = $/s × billed seconds (provider-reported, with the Kling-with-video rule) + fixed extras. Failures and refusals refund in full: `provider_failed`, `provider_refused`, `provider_timeout`, `provider_out_of_credit` (which also notifies owners for Replicate).
- **Caps:** the suite's own per-shot cap (`SUITE_CAP_PER_JOB_USD`, $5) and per-day cap (`SUITE_CAP_PER_DAY_USD`, $25 across the studio's suite jobs today). The owner can change both, and the wallet's usual per-job, per-day and per-user-day caps apply as well.
- **Character swap** is `mode: "swap"`: an adapter over the existing Replicate engine (`POST /v1/jobs` with `engine: "replicate"`). Cinema maps to HD.

## Suite prompts through prompt scripts (workstream 4): done 2026-11-05
_Code: `src/suite/scripts.ts` (both scripts, registered on load), `plan.ts` (`run('suite.shot')`), `compile.ts` (`run('suite.camera')`), `runner.ts` (beat-only audio), `service.ts` (`resolveSpeaking`). Tests: `test/suite-scripts.test.ts`._

**Engine fix found while porting:** rule lists come back from Postgres `jsonb` with object keys reordered, so a saved list failed the "locked rule unchanged" check whenever a locked rule had conditions, and silently fell back to the defaults. `same()` in `prompt/scripts/run.ts` now compares key-order independently.

**Script `suite.camera`** (format `lines`, one section `camera`, kind `system`):
- **Inputs:** `vocab` (enum kling/seedance/h3/veo/generic), `hasMove`, `hasFraming`, `hasRig`, `hasLight`, `hasPalette`, `hasStyle`, `hasPerformance`, `presets`.
- **Rules:** one per vocab, each with condition `vocab is X`. Each rule places that vocab's format block (`suite.camera.format.<vocab>`).
- **Vars:** `move`, `framing`, `rig`, `light`, `palette`, `style`, `performance`. The compiler computes them in code from the `suite.camera.*` wording lines and the per-model rules:
  - the one-move rule
  - mix compatibility
  - the LTX camera enum
  - the guide clip, used only on models that take a reference video
- **Presets switch:** the style rules are `optional`, so switching Presets off leaves only the move and the framing.

**Script `suite.shot`** (format `lines`). Each section and what fills it:

| Section | Kind | Filled by |
|---|---|---|
| character | system | either `suite.shot.character` (tokens) or a new words-only block, chosen by `hasCharacterImages` |
| outfit | system | — |
| refs | system | `each` over `refs` items `{token, role, label}` |
| lock | system | only when `roles` has more than one member |
| frames | system | — |
| **scene** | **user** | the user's prompt and direction through `{direction}`, with workstream 4's sanitiser |
| guide | system | `each` over `videos` items `{token, use}` |
| camera | system | the rendered `suite.camera` text as a var |
| audio | system | workstream 4's `audio.lipsync` / `audio.beat` / `audio.silent` blocks, chosen by `audio` (speech/music/none) and `speaking` |
| avoid | system | — |
| footer | system | — |

**Audio:**
- `ShotRequest.speaking` (added; default false) is the talking flag.
- With a source clip it is pre-set from `detectTalking`.
- When audio references are added, non-speaking shots send `beatOnlyAudio`'s instrumental instead of raw audio.

**Confirmed with workstream 4 (their head 5b96d54):**
- **Group:** `suite` stays, and so does the concat into PROMPT_DEFS. `registerPromptDefs` is optional.
- **Registration:** the scripts are registered with `registerScript()`.
- **User text:** the user's text goes through `sanitizeDirection(direction, identity, texts)` before `run()`, and its `removed` list is returned with the result. `suite.shot.scene` = `{direction}` is the script's only user section.
- **Speaking:** `speaking` is the one switch for both the audio and the mouth wording.
  - **On:** send the speech audio and use the lip-sync line.
  - **Off:** send `beatOnlyAudio(...)`'s instrumental only. It runs synchronously inside the job, and its `costUsd` is added to the job's bill. Use `audioLine({audio: 'music', speaking: false})`.
  - **Nothing sent:** use `audioLine({audio: 'none', speaking})`, or `suite.audio.dialogue` when she is speaking.
- **Pre-set:** `speaking` is pre-set from `detectTalking` when the user brings an audio or video reference.
- **Mouth wording:** it comes only from these audio rules, never from camera or performance blocks. The regex guess is gone; it went in 07c9128.

### Who is who
- **The cast list:** `cast[]` holds `personIndex` (order of appearance or left to right), `personHint` (left/center/right/foreground/background/first…fourth), `personNote` (free words) and `faceCrop`. Face crops are sent only where the model takes them (the Kling models) and are named "<Image k> shows which person … is".
- **Ordering:** the cast is sorted by index, then by hint (left → right), then as given. Models that map references left to right get them in that order.
- **References per person:** each person gets `refsPerPerson` images, within the model's image budget. Priority: dressed in the outfit (outfit front), face front, body front, profile, …. One-photo models without an outfit get the full-body front.

### Speaking and sound (the lip-sync rules)
- **Per person:**
  - **The switch:** `cast[i].speaking`.
  - **One person, no switch:** the clip's switch → upload talking flag → detection.
  - **Several people:** "unknown", and the mouth follows the clip.
- **Mouth wording:** only from the script's rules — "lips match every word of the original audio" / "mouth follows the source exactly; she does not speak, sing or mouth words" / "mouth follows the source exactly".
- **Sound:**
  - `keepAudio` (default on) keeps the original sound. On models that don't return it (`keepsAudio: false`), it is put back with `restoreAudio` (video stream copy, no re-encode, no trim).
  - `keepAudio: false` strips it.

### Prompt script `suite.recast` (owner-editable)
- **Sections:** task → each person → who is who (face crops) → cast lock (several people) → mouths (per person) → cuts (models that keep them) → the user's direction (the only user section, sanitised against every cast member's identity and never-add list) → closing line.
- **Blocks:** `suite.recast.*` (task, person, identify, lock, mouth.speaking / mouth.silent / mouth.follow, cuts, direction).

### Money
- **Estimate:** $/s (with video input) × billed seconds × takes. The hold uses the same caps as any suite shot.
- **Settle:** exact billed seconds from the provider. Mock mode settles $0 ("test render").
- **Billed seconds:**
  - The fal minimum length is 5 s.
  - Kling 4.0 edits bill output + input seconds.
